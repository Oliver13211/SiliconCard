# 硅牌 SiliconCard · 游戏设计报告

> 版本 v1.0 · 2026-10-01
> 状态：✅ 用户审核通过（2026-10-01），作为项目设计基线；开放问题已在 §7 拍板

---

## 1. 项目概述

**一句话**：显卡与硬件圈热梗主题的 1v1 回合制卡牌对战网页游戏。炉石传说式规则骨架 + Three.js 3D 牌桌 + React HUD。

**设计支柱**（所有后续决策的判断标准）：

1. **梗即玩法**——每个机制都源自真实硬件痛点/热梗（烧接口、矿卡、驱动玄学），而不是贴皮装饰；
2. **规则即双关**——关键词全部梗化命名（嘲讽→信仰充值），规则书读起来本身就是段子；
3. **引擎无头**——规则内核与渲染零耦合，同一内核驱动三种对手：内置人机、外部 AI Agent、局域网真人；
4. **内容数据驱动**——卡牌与派系全部 JSON 定义，派系可无限扩展（三大厂 → 苹果 → 高通 → ARM Mali → 未来的任何 GPU IP 厂）。

**目标用户**：硬件圈玩家、梗文化受众、想让 AI agent 打牌的开发者。

**平台**：桌面浏览器优先（纯前端静态站点，GitHub Pages 可部署）；移动端适配为后期事项。

## 2. 核心规则设计

### 2.1 基础盘（炉石概念 → 硅牌映射）

| 炉石概念 | 硅牌映射 | 数值/说明 |
|---|---|---|
| 英雄 | 玩家扮演一颗 **CPU** | 体质（血量）**30**，"同型号看体质"的硅彩票梗 |
| 法力水晶 | **功耗瓦数（W）** | 每自身回合 +100W，上限 **1000W**，即"电源供电"；卡牌功耗建议直接用真实 TDP（5090=575W） |
| 随从 | **显卡**（站场单位） | 攻/血属性，场上上限 **7** 个（"扩展槽"） |
| 法术 | **驱动 / 事件** 牌 | 出牌即结算，不站场 |
| 武器/装备 | **配件** 牌 | 散热器、电源、主板等，持续光环或一次性 |
| 英雄技能 | **派系技能** | 2W，每派系一个，派系差异化的抓手 |

### 2.2 回合流程

1. **回合开始**：供电上限 +1（至多 10）→ 结算"跳闸"恢复 → 抽 1 张牌；
2. **出牌阶段**：任意次出牌 / 使用派系技能（受功耗限制）；
3. **攻击阶段**：己方显卡可攻击（未超频的入场当回合不可攻击）；
4. **回合结束**：手牌上限 10，超出 burn 掉；触发回合结束类效果。

### 2.3 关键词（炉石关键词 → 梗化，M1 全部实装）

| 关键词 | 炉石原型 | 效果 | 梗点 |
|---|---|---|---|
| **信仰充值** | 嘲讽 | 敌方攻击必须先指定此单位 | 公版涡轮卡、信仰灯 |
| **三年质保** | 圣盾 | 抵挡第一次受到的伤害，触发后消失 | 质保用掉了 |
| **超频** | 冲锋 | 入场当回合即可攻击 | 一键冲 5.8GHz |
| **双芯 GPU** | 风怒 | 每回合可攻击两次 | Titan Z 双芯 |
| **蓝屏 / 传家宝** | 亡语 | 死亡时触发效果 | 矿卡亡语=给对面留遗产 |
| **无输出亮机** | 潜行 | 攻击前不可被敌方指定 | 亮机卡的卑微 |
| **跳闸** | 过载 | 本回合强力，下回合部分功耗被锁 | 80PLUS 白牌电源 |

### 2.4 派系与英雄技能（200W，可无限扩展的数据定义）

| 派系 | 技能名 | 效果 | 梗点 | 实装批次 |
|---|---|---|---|---|
| NVIDIA | DLSS | 己方一张显卡 +1 攻 | 帧生成 | M1 |
| AMD | 开光追试试 | 1 点直伤，30% 概率失败 | 光追垃圾（黑红梗） | M1 |
| Intel | 驱动更新 | 抽一张牌 | Arc 驱动玄学 | M1 |
| 中立（通用硬件） | 清灰 | 1 点直伤 | 十年老机箱 | M1 |
| Apple Silicon | 能效比 | 自身 +2 护甲 | 不发热=散热好 | M4 |
| 高通 Adreno | TOPS 营销 | 随机己方显卡 +1/+1 | AI PC 营销词 | M4 |
| ARM Mali | 公版方案 | 召唤 1/1 亮机卡 | 公版小核 | M4 |

### 2.5 法术/事件牌示例（风味参考，正式数值 M1 平衡期定）

「12VHPWR 熔毁」（摧毁一张显卡）、「矿难」（全场矿卡 -2/-2）、「显卡撕裂者」（对敌方 CPU 直伤）、「矿卡重生」（从弃牌堆捞回显卡）、「性价比真香」（复活己方上一张死亡的显卡）、「DLSS 4」（一张显卡本回合攻击翻倍，帧生成）、「驱动回滚」（移除一个敌方显卡的关键词）。

### 2.6 卡牌数据 Schema（content 包的 JSON 定义，示例）

```json
{
  "id": "rtx-5090",
  "name": "RTX 5090",
  "faction": "nvidia",
  "type": "gpu",
  "cost": 575,
  "attack": 9, "health": 7,
  "keywords": ["overclock"],
  "rarity": "legendary",
  "effect": "battlecry_burn_connector",
  "flavor": "609W？不，是信仰的代价。",
  "art": { "shape": "gpu_triple_fan", "palette": "nvidia", "glow": "green" }
}
```

- `type`: `gpu`（随从）| `driver`（法术）| `accessory`（配件）
- `effect`: 效果函数注册 ID，引擎内实现原语组合，与 JSON 数据分离
- `art`: 程序化卡面渲染参数（几何形、派系色板、辉光），不依赖图片资产

### 2.7 胜负与疲劳

- 对方 CPU 体质 ≤ 0 → 胜利（结算画面：「R.I.P 烧了」）；
- 牌库抽空后再抽牌 → 疲劳递增伤害（炉石同款，防无限拖时）。

### 2.8 美术路线

程序化风格化：卡面由数据驱动、Canvas 程序化绘制（派系色板 + 几何抽象形 + 图标），**零外部图片资产、零版权风险**，风格统一可持续；后期可逐卡替换为 AI 插画。不使用真实产品渲染图；卡名使用真实型号属戏仿/评论范畴，风险与备选方案（虚构型号）见 §7 开放问题。

## 3. 系统架构设计

### 3.1 Monorepo 包结构（yarn workspaces）

```
SiliconCard/
├── packages/
│   ├── core/        @siliconcard/core    无头规则引擎（纯 TS，零运行时依赖）
│   ├── content/     @siliconcard/content 卡牌/派系/关键词 JSON 数据包（可 mod）
│   ├── ai/          @siliconcard/ai      内置人机（Easy/Normal/Hard 启发式）
│   ├── client/      网页端（React + Three.js + Vite）
│   ├── server/      @siliconcard/server  LAN 对战服务端（Node + ws）
│   └── cli/         @siliconcard/cli     Agent 对战接口（stdin/stdout JSON）
└── docs/            设计文档、规则速查（Agent 用）
```

### 3.2 Core 引擎 API 与三条铁律

```ts
engine.initGame(deckA, deckB, seed)              // 开局
engine.applyAction(state, action)                // => { state', events[] }，非法操作抛 RuleError
engine.getLegalActions(state, playerId)          // 合法动作集：AI / Agent / UI 校验共用
engine.viewFor(state, playerId)                  // 视角裁剪：联机时对手手牌不可见
```

1. **确定性**：随机数走引擎内置种子 RNG，`seed + 动作序列` 唯一决定对局 → 回放、联机同步、AI 自对弈测试全部免费获得；
2. **状态可序列化**：`GameState` 是纯 JSON → LAN 传输、CLI 输出、测试快照零成本；
3. **事件驱动**：引擎产出 `events[]`，UI 动画/日志/音效全部消费事件流。

初始事件目录（渲染与日志的契约，~16 种）：`GAME_START / TURN_START / TURN_END / CARD_DRAWN / CARD_PLAYED / MINION_SUMMONED / MINION_DIED / ATTACK_DECLARED / DAMAGE_DEALT / HEALING / KEYWORD_TRIGGERED / HERO_POWER_USED / FATIGUE / BURN_OUT(跳闸) / ARMOR_GAINED / GAME_END`。

### 3.3 适配器（对局来源）

- **单机 PvE**：玩家 UI 直接驱动引擎，内置 AI 读 `getLegalActions` 出招；
- **LAN 对战（M2）**：Node ws 权威服务端持有完整 state，客户端只收 `viewFor` 裁剪视图；上行仅 `{type:'action'}`；房间支持 IP 直连 + mDNS 自动发现；seq 序号支持断线重连；内置 AI 可作为服务端虚拟玩家；
- **Agent 接口（M3）**：CLI JSON 行协议——引擎输出 `{state, legalActions}`，外部 Agent 回 `{action}`；`docs/` 提供规则速查 skill 文档；后续可包 MCP server。

### 3.4 客户端渲染架构

- Three.js 不进 React 树：canvas ref + 独立场景管理器；卡牌 = PlaneGeometry + CanvasTexture 程序化卡面；动画由事件流驱动（抽牌飞入、烧卡冒烟、跳闸闪屏）；raycasting 处理 3D 点击；
- React HUD：zustand 订阅引擎事件（血量、功耗、手牌、日志、菜单）；
- 性能：卡牌 mesh 池化、纹理缓存、动画可快进。

### 3.5 技术栈清单

TypeScript 5 · React 19 · Three.js · Vite · yarn workspaces（Yarn 4）· zustand · ws · vitest · tsx（CLI）· GitHub Actions。

### 3.6 测试策略

- core：vitest 单测 + **黄金回放**（固定 seed+动作序列做快照回归）；
- 每张卡的特效函数独立单测；
- 联机：双客户端脚本对跑集成测试；
- 视觉：渲染截图 + visual-judge 验收。

## 4. 交付里程碑

> ✅ 已确认（2026-10-01）：Agent 接口先于局域网对战（M1 → M3 → M2）。

| 里程碑 | 内容 | 出口标准 |
|---|---|---|
| **M0 立项基建** | workspaces + Vite + React + TS 脚手架；core/content 骨架与类型定义；GitHub Actions CI（lint+test+build）；AGENTS.md、docs | CI 绿，骨架可跑 |
| **M1 可玩 MVP** | 引擎全量规则；首批卡池 ~60 张（N/A/I + 中立）；内置 AI（Normal）；客户端完整闭环（主菜单→选派系→3D 对战→结算）；基础演出+占位音效；**GitHub Pages 上线** | 陌生人打开链接能完整打一局 |
| **M3 Agent 接口** | CLI JSON 行协议、规则速查 skill 文档、演示 agent；（可选）MCP 包装 | 外部 AI agent 能通过 CLI 打完整一局 |
| **M2 局域网对战** | ws 权威服务端、房间+mDNS 发现、断线重连、服务端 AI 虚拟玩家、联机 UI | 同局域网两台设备对战 |
| **M4 内容量与平衡** | Apple/高通/ARM 派系卡池、新梗卡、黄金回放+自对弈平衡管线 | 派系 ≥7，平衡报告产出 |

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 与炉石规则相似度 | 游戏机制本身不受版权保护；命名 100% 原创梗化、美术零复用（程序化卡面） |
| 真实型号名的商标问题 | 卡名+戏仿描述属评论/戏仿范畴，同人开源项目常见做法；保留虚构型号备选（见 §7） |
| Three.js 演出工作量失控 | 演出规格分级（基础/进阶），M1 只做基础动画，事件驱动架构保证后期可加 |
| 卡牌平衡失控 | 黄金回放 + AI 自对弈统计管线（M4），数值全部在 content JSON 里可热调 |
| AI 强度不足 | 启发式起步（场面交换+直伤择优），架构支持后续换 MCTS |

## 6. 明确不做（YAGNI）

- 在线匹配/天梯/账号系统（M2 只做局域网点对点）；
- 移动端原生 App；
- 真实产品图片资产；
- 卡牌交易/掉落等任何商业化机制。

## 7. 已拍板决策（2026-10-01 审核通过）

1. **M2/M3 顺序**：Agent 接口先于局域网对战（M1 → M3 → M2）；
2. **卡名商标尺度**：直接使用真实型号名（RTX 5090、RX 9070 XT 等）；
3. **黑红梗尺度**：圈内自嘲向全开（A 卡光追、烧接口等），红线为不攻击真实个人。
