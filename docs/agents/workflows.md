# 硅牌 SiliconCard · 标准 Workflow

> 配套：[presets.md](./presets.md)（agent 预设） · [task-breakdown.md](../task-breakdown.md)（任务清单）
> 每种任务类型一条标准流程。通用骨架先行，各类型只写增量步骤。

---

## 通用骨架（所有任务的默认流程）

```
1. 领任务      从 task-breakdown.md 取任务 ID，读取对应 agent 预设
2. 补上下文    读 AGENTS.md → design-report.md → 预设 → 相关契约（规则书/事件目录/schema）
3. 实现        在允许范围内改动；契约变更须先发提案（见 WF-ENGINE）
4. 自验        测试全绿 + 类型检查 + lint；按任务类型追加专项自验
5. 汇报        改动文件清单 + 测试结果 + 验收标准逐条对照 + 遗留问题
6. 审查合并    人工/AI review 通过后合并；CI 必须绿
```

---

## WF-ENGINE · 引擎规则变更（最高风险级别）

**触发**：任何 `GameState/Action/GameEvent` 结构变化、规则语义变化、新效果原语。

```
1. engine-dev 产出变更提案：动机 + 类型 diff + 受影响的黄金回放预估
2. 人工确认后实现（core 包内）
3. 跑黄金回放 → 每条漂移归因为「预期变更 / 意外回归」
   - 意外回归：修复；预期变更：更新快照并在提交信息中说明
4. 下游影响通报（必须逐个 @ 对应预设）：
   - card-content：效果原语变化 → 卡池适配
   - client-3d：事件目录变化 → 动画映射补齐
   - client-ui：合法动作/状态字段变化 → HUD 适配
   - qa-balance：回放快照基线更新
5. 全部下游确认后关闭变更
```

**红线**：未走通报的规则变更禁止合并；`core` 禁止引入运行时依赖。

## WF-CARD · 新增卡牌

**触发**：M1-CNT1..4、M4-CNT5 及后续所有扩卡。

```
1. card-content 按 schema 写 JSON（数值/关键词/flavor/art 参数）
2. 效果用已有原语组合表达；表达不了 → 停，输出「新原语提案」走 WF-ENGINE
3. 三件套自验：单测（效果触发/不触发/边界）+ 引擎实打 + 卡面渲染检查
4. 梗味自审：圈内人能否秒懂？效果与梗是否有因果？
5. 提交；qa-balance 将新卡纳入下轮自对弈统计
```

**批量并行**：多张卡可开多个 card-content 并行，互不依赖；同派系数值强度由 qa 报告统一校准。

## WF-VISUAL · 视觉/演出交付

**触发**：M1-R3D1..4、M4-R3D5、任何用户可见的画面改动。

```
1. client-3d / client-ui 实现并自验（逻辑测试）
2. 渲染目标页面/场景截图（含关键交互态：手牌展开、目标选择、结算画面）
3. 交 visual-judge（视觉验收 agent）按用户接受度标准评审：
   布局破版、文字可读性、风格一致性、卡面辨识度
4. 不通过 → 修复 → 回到第 2 步（单循环，最多两轮后升级人工）
5. 通过 → 提交
```

**红线**：Three.js 场景不进 React 渲染树；卡面禁止外部图片资产。

## WF-NET · 联机协议变更

**触发**：消息格式、房间流程、重连语义的任何改动。

```
1. net-dev 同步修改 server 与 client/net 两端（同一提交）
2. 更新协议文档（docs/protocol.md）与版本号
3. 双客户端脚本对跑 100 局：状态零漂移 + 重连场景覆盖
4. 旧客户端兼容性评估：不兼容必须升协议版本并在 UI 提示刷新
```

## WF-AGENT · Agent 接口变更

**触发**：CLI 协议、skill 文档、输出格式的任何改动。

```
1. agent-liaison 修改 cli 包 / docs/agent-skill.md
2. 契约测试：协议样例消息往返（state 输出 → action 输入）全部通过
3. 终审 = 新会话 coding agent 仅凭 skill 文档打满一局（人类零干预）
4. 不通过 → 以失败日志反推接口可用性问题 → 修改 → 重跑
```

## WF-BALANCE · 平衡调整

**触发**：M4-QA2 及后续一切数值调优。

```
1. qa-balance 批量自对弈（≥1000 局）→ 平衡报告（派系胜率/卡牌出场率/贡献度）
2. 报告给出建议档位（数值区间），不改代码
3. card-content 按建议改 content JSON（只动数据，不动逻辑）
4. 黄金回放回归（预期漂移则更新快照）→ 新一轮报告确认收敛
```

## WF-RELEASE · 发布

**触发**：M1-INF4、M2 上线、任何对外可玩版本。

```
1. CI 全绿（lint + test + build）
2. devops 构建 client 产物 → 部署 GitHub Pages
3. 线上冒烟：开一局人机对局全流程走通
4. 打 tag + 更新 README 的"开发状态"节
```

## 流程选择速查

| 我要… | 走哪条 |
|---|---|
| 改引擎类型/规则/事件 | WF-ENGINE |
| 加一张卡 | WF-CARD |
| 改画面/动画/卡面 | WF-VISUAL |
| 改联机消息 | WF-NET |
| 改 CLI/skill 文档 | WF-AGENT |
| 调数值平衡 | WF-BALANCE |
| 发新版本 | WF-RELEASE |
| 其他 | 通用骨架 |
