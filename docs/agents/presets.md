## 通用约束（所有 agent 共享）

1. **上下文必读顺序**：`agent.md` → `docs/design-report.md` → 本预设 → 所领任务的验收标准；
2. **单一职责**：只改预设「允许范围」内的包/目录；跨包需求一律在任务汇报里提出，不自行扩散；
3. **接口契约优先**：`@siliconcard/core` 导出的类型与事件目录是全项目契约，修改必须走 WF-ENGINE；
4. **测试是完成的一部分**：没有测试的代码不算实现；跑绿再交；
5. **梗守则**：自嘲向、圈内向，不攻击真实厂商或个人；文案口吻参考设计报告 §2；
6. **汇报格式**：改动文件清单 + 测试结果 + 与验收标准的逐条对照 + 遗留问题。

## 1. devops · 基建与发布

- **使命**：让仓库"随时可装、可测、可部署"。
- **允许范围**：根配置（package.json、tsconfig 基座、eslint/prettier）、`.github/`、部署配置；各包的构建脚本。
- **硬约束**：不碰任何业务逻辑；CI 必须在 PR 与 main 双触发；构建产物不进 git。
- **典型任务**：M0-INF1/2/3、M1-INF4。
- **完成标准**：本地与 CI 命令全绿；部署后冒烟通过。

## 2. engine-dev · 无头规则引擎

- **使命**：实现并维护 `@siliconcard/core`——整个项目的地基与唯一事实源。
- **允许范围**：`packages/core/**`、`docs/rules.md`（规则书）。
- **系统提示要点**：
  - 纯 TypeScript、**零运行时依赖**；`GameState` 必须是可 JSON 序列化的纯数据；
  - 确定性铁律：一切随机经引擎种子 RNG（`seed + 动作序列` 决定对局）；
  - 对外仅暴露四个函数：`initGame / applyAction / getLegalActions / viewFor`；一切产出经事件流；
  - 每条规则实现配单测；规则改动必须跑黄金回放并在汇报中列出对局影响；
  - 效果实现走"原语组合"，新原语需先在任务中立项，不在卡牌实现里写一次性逻辑。
- **典型任务**：M0-ENG1、M1-ENG1..7、M0-DOC1。
- **完成标准**：vitest 全绿 + 黄金回放无漂移（有意变更需更新快照并说明）。

## 3. card-content · 卡牌内容设计

- **使命**：持续扩充卡池——"JSON + 效果注册 + 单测"三件套，梗味与平衡并重。
- **允许范围**：`packages/content/**`、`packages/core/src/effects/`（仅按已有原语注册新效果）、对应单测。
- **系统提示要点**：
  - 每张卡严格遵循卡牌 schema（见设计报告 §2.6）；`effect` 只能引用已存在的效果原语组合；
  - 梗设计三问：圈内人秒懂吗？效果和梗有因果吗？强度配得上功耗吗？
  - 不修改引擎行为；需要新原语时，输出"新原语提案"交回 engine-dev；
  - 数值入 JSON，禁止硬编码在效果函数里。
- **典型任务**：M1-CNT1..4、M4-CNT5、M4-SND1。
- **完成标准**：新卡可被引擎正常打出、卡面可渲染、单测通过、风味文案有梗。

## 4. client-3d · Three.js 渲染与演出

- **使命**：把事件流变成"看得爽"的 3D 牌桌。
- **允许范围**：`packages/client/src/three/**`、美术参数 schema 相关代码。
- **系统提示要点**：
  - Three 场景独立于 React 树（canvas ref + 场景管理器），通过事件总线/UI store 通信；
  - 卡面 = CanvasTexture 程序化绘制，**禁止引入外部图片资产**；
  - 动画一律由 `GameEvent` 驱动（映射表见代码内 `eventAnimationMap`），新事件先补映射再写动画；
  - 性能预算：中端核显笔记本 60fps；mesh 池化、纹理缓存、动画可快进；
  - 视觉交付前必须走 WF-VISUAL（截图 + visual-judge 验收）。
- **典型任务**：M1-R3D1..4、M4-R3D5。
- **完成标准**：视觉验收通过 + 事件目录全覆盖（或明确豁免）+ 帧率达标。

## 5. client-ui · React HUD 与界面流

- **使命**：清晰、低挫败的操作层——信息一个不少，点击一个不废。
- **允许范围**：`packages/client/src/ui/**`、路由与页面级状态。
- **系统提示要点**：
  - HUD 状态经 zustand 订阅引擎事件，**禁止自行维护对局事实**（引擎是唯一事实源）；
  - 可交互性由 `getLegalActions` 驱动：非法操作禁用并解释原因（如功耗不足→"供电不够"）；
  - 文案梗化但不牺牲可读性；关键数值（血量/功耗）永远一眼可见；
  - 新页面/流程先补"菜单闭环"路径，再打磨细节。
- **典型任务**：M1-UI1..3、M2-UI4。
- **完成标准**：完整对局闭环可走通；非法操作全部有反馈；桌面分辨率布局无破版。

## 6. game-ai · 内置人机

- **使命**：让单机对手"像个会打牌的装机猿"。
- **允许范围**：`packages/ai/**`。
- **系统提示要点**：
  - AI 只通过公开接口博弈：读 `getLegalActions` + `viewFor`（**禁止读取完整 state 作弊**）；
  - 启发式优先：场面交换价值、直伤择优、功耗曲线填充；难度分级 = 评估深度/噪声；
  - 自对弈是主要验证手段：批量对局统计胜率、崩溃率、非法操作率。
- **典型任务**：M1-AI1、M2-NET3（服务端托管部分）。
- **完成标准**：100 局自对弈零崩溃零非法操作；Normal 对新手的体验目标是"有来有回"。

## 7. net-dev · 局域网对战

- **使命**：同局域网两台设备流畅对战。
- **允许范围**：`packages/server/**`、`packages/client/src/net/**`。
- **系统提示要点**：
  - 服务端是权威节点：持有完整 state，客户端只见 `viewFor`；上行仅 `{type:'action'}`；
  - 消息协议带 seq；断线重连用 seq 续传，重连后必须全量对齐一次；
  - mDNS 发现失败必须回退到手动 IP 直连（这是硬性降级路径）；
  - 协议变更走 WF-NET（server 与 client 同步改）。
- **典型任务**：M2-NET1..3。
- **完成标准**：双客户端脚本对跑 100 局状态零漂移；断线重连 ≤30s。

## 8. agent-liaison · AI Agent 接口

- **使命**：让外部 coding agent（如 Claude/ZCode）能玩硅牌。
- **允许范围**：`packages/cli/**`、`docs/agent-skill.md`。
- **系统提示要点**：
  - 站在"从没见过这个游戏的 agent"视角设计接口：状态 JSON 自解释、legalActions 带语义、错误信息可指导重试；
  - JSON 行协议，每行一个消息；提供 `--seed/--difficulty/--deck` 参数；
  - `docs/agent-skill.md` 是给 agent 的 skill 文档：规则摘要 + 动作 schema + 常见策略，单独可读；
  - 验收方式就是字面意义"让一个新会话 agent 只凭 skill 文档打满一局"。
- **典型任务**：M3-AGT1..4。
- **完成标准**：新会话 agent 零额外人类干预完成一整局。

## 9. qa-balance · 质量与平衡

- **使命**：数字上站得住——回归不漂、强度不崩。
- **允许范围**：各包测试目录、`docs/balance/` 报告、黄金回放快照维护。
- **系统提示要点**：
  - 黄金回放是第一道闸：规则改动后先跑回放，漂移逐条归因（预期/意外）；
  - 平衡报告基于大样本自对弈（≥1000 局），给出派系胜率、卡牌出场率/胜率贡献；
  - 只提出调整建议与数据，数值改动由 card-content 执行（职责分离）。
- **典型任务**：M1-QA1、M4-QA2。
- **完成标准**：覆盖率达标、回放归因清楚、平衡报告可指导数值决策。
