## 0. 决议记录与总览

### 0.1 五项决议（2026-10-10 用户拍板）

| # | 决议项 | 结论 |
| --- | --- | --- |
| 1 | 实施顺序 | **按原案 α → β → γ**（回放快赢 → 拟真观感 → 教程与平衡） |
| 2 | 先手平衡方案 | **方案 B「电费抵扣券」**——后手起手附加一次性卡，本回合 +300W 可超上限 |
| 3 | 回放存储 | **浏览器本地存储**（IndexedDB 承载回放体，localStorage 仅存偏好），**JSON 格式化导入导出为一等公民功能** |
| 4 | 教程卡 | **不新增教学专用卡**，教程卡组全部从现有 90 卡池组装 |
| 5 | 快捷键 | **一期即做自定义键位**：默认键位 + 自定义编辑 + 浏览器本地持久化 |

> 术语说明（决议 3/5 的「cookie」）：实现按 Web 平台语义落地——回放体走 **IndexedDB**（localStorage 约 5MB 上限，放不下几十局回放；IndexedDB 配额以 MB 计），偏好类小数据（键位/音量/动效偏好）走 **localStorage**。两者都是纯浏览器本地持久化，不经服务器。

### 0.2 目标总览

一期解决了「有得玩、玩得好」；二期解决「玩得深、留得住」：

1. **观感再上一档**——拟真材质取代扁平观感，界面信息可读性重排，卡牌效果可视化预览；
2. **复盘闭环**——回放（本地存储 + JSON 导入导出）+ AI 复盘 + 数值面板；
3. **新玩家通道**——体系化教程（零教学专用卡）把规则学习融进模拟对战，图鉴兜底查阅；
4. **竞技公平**——电费抵扣券补偿 +9pp 先手优势；
5. **手感杂项**——自定义快捷键出牌。

**不做（延续 YAGNI）**：天梯/账号系统、服务器持久化对战记录、移动端适配、卡池商业化、云端回放分享站。回放分享走导出 JSON 文件。

## 1. 批次 α · 回放闭环 + 图鉴 + 快捷键

### P2-INF1 回放录制与浏览器本地存储

- **执行 agent**：client-ui ｜ **依赖**：无 ｜ **工作量**：S-M
- **内容**：
  1. battleDriver 在对局中静默记录 `setup（seed + 双方卡组 + 派系）+ 动作序列`，复用 core 的 `ReplayRecording` 序列化与 canonicalJson；
  2. GAME_END 落 **IndexedDB**：元数据索引（日期/对阵派系/胜负/局长/种子/schemaVersion）与回放体分 store 存放；
  3. 容量策略：本地保留**最近 50 局**（LRU 淘汰），手动删除任意局；
  4. **JSON 格式化导出**（一等公民）：pretty-print（2 空格缩进）、分区注释结构（`meta` / `decks` / `actions` / `checksum`），单文件单局，命名 `siliconcard-replay-<日期>-<种子>.json`——人类可读、可 diff、可直接喂给外部 AI agent 分析（呼应 M3 Agent 资产）；
  5. **JSON 导入**：拖拽或文件选择 → `schemaVersion` 校验 + stableHash 完整性校验 → 入库；版本不符/损坏给出明确错误提示；
  6. 回放列表页：按日期筛选、看对阵与胜负、删除、导出、导入。
- **验收标准**：
  - 本地/人机/局域网三种对局来源全部自动录制；
  - 导出的 JSON 手工可读，重新导入后可完整回放且 stableHash 一致；
  - 第 51 局完成时最旧一局被淘汰；删除/导入操作不破坏其余记录；
  - 损坏或版本不符的导入文件被拒并提示原因，不污染回放库。

### P2-UI2-1 效果白话翻译器（公共基建）

- **执行 agent**：card-content（翻译规则表）+ client-ui（解释层接口）｜ **依赖**：无 ｜ **工作量**：M
- **内容**：把 EffectSpec 步骤序列翻译成中文人话（`{op:'damage', target:{kind:'chosen',pool:'anyCharacter'}, amount:3}` → 「出战吼：指定任意一个角色，造成 3 点伤害」）。覆盖 12 效果原语 × TargetSelector 全组合、七关键词、光环/亡语触发语义；纯声明式规则表，放 content 侧解释层（数据驱动铁律），引擎零改动。
- **验收标准**：
  - 90 张卡 + 3 张派系技能 + 抵扣券（P2-ENG1 落地后）全部有白话解释，无漏网（漏网回退显示结构化步骤而非空白）；
  - 翻译表为纯数据，新增卡自动获得解释；
  - 无头单测：全卡池扫描断言每张卡的翻译非空、含关键数值。

### P2-UI3 回放播放器

- **执行 agent**：client-ui（驱动器/控制条）+ client-3d（演出复用）｜ **依赖**：P2-INF1 ｜ **工作量**：M
- **内容**：
  1. 按录制动作序列重驱引擎（确定性保证逐帧一致），复用 battleDriver + 三维场景全量演出与音效；
  2. 控制条：播放/暂停/变速（0.5×/1×/2×/4×）/逐事件步进/时间轴拖动（seek = 引擎从头快放至目标事件，毫秒级重放）；
  3. **上帝视角**：回放中双方手牌全量可见（复盘用，区别于对局 viewFor 限制）；
  4. 事件日志侧栏与时间轴双向联动，点日志跳转对应时刻；
  5. 播放器快捷键（复用 P2-UI5 键位体系）：播放/暂停、步进、变速、退出回放。
- **验收标准**：
  - 任意一局从任意事件点继续播放，状态与原局一致（抽查 stableHash 对齐）；
  - 时间轴标记攻击/召唤/传说入场/跳闸等关键事件，点击精确跳转；
  - 演出与音效在回放中完整；hash 校验失败的回放明确提示「与当前卡池版本不符」并只读开放。

### P2-UI4 全卡牌图鉴

- **执行 agent**：client-ui ｜ **依赖**：P2-UI2-1（白话解释）｜ **工作量**：M

  - 筛选全组合正确；新卡入池后图鉴自动出现（以 mock 卡注册表测试验证）；

### P2-UI5 自定义快捷键（含默认键位）

- **执行 agent**：client-ui ｜ **依赖**：无 ｜ **工作量**：M
- **内容**：
  1. **固定命令集**（命令与解耦的键位）：`play_slot_1..10` / `end_turn` / `hero_power` / `cycle_target` / `confirm` / `cancel` / `fast_forward` / `mute` / `toggle_key_hints` / `help` / 回放命令（`replay_play_pause` / `replay_step` / `replay_speed`）；
  2. **默认键位**：`1-9、0` 出牌 / `空格` 结束回合 / `H` 英雄技能 / `Tab` 循环选目标 / `Enter` 确认 / `Esc` 取消 / `F` 快进 / `M` 静音 / `?` 键位表；
  3. **键位编辑器**（设置面板）：点命令 → 按新键（支持 Shift/Ctrl/Alt 修饰组合）；**冲突检测**——新键已被占用时提示并要求交换或改选；恢复单条默认 / 一键全部重置；
  4. **持久化**：localStorage `siliconcard.keybinds.v1`（版本化 schema，容错解析，损坏回退默认键位）；
  5. 槽位角标实时显示当前键位（可开关）；输入框聚焦时快捷键全部失活；对战与回放模式键位分离互不干扰。
- **验收标准**：
  - 不碰鼠标用默认键位完成一整局；
  - 自定义修改 → 刷新页面 → 键位保留；损坏 localStorage 数据自动回退默认且不报错；
  - 冲突被检出；一键重置恢复默认；`?` 键位表与实际行为一致。

### P2-DATA1 数值面板

- **执行 agent**：client-ui（面板）+ qa-balance（全局数据生产）｜ **依赖**：P2-INF1（个人历史部分）｜ **工作量**：S-M

## 2. 批次 β · 拟真材质 + 预览 + 可读性

### P2-R3D1 拟真卡牌材质

- **执行 agent**：client-3d ｜ **依赖**：无（可与 α 尾段并行）｜ **工作量**：M
- **内容**：
  1. 卡牌材质升级 `MeshPhysicalMaterial`：卡面 Canvas 生成时同步派生**法线贴图**（边框浮雕、插画窗下沉、金属框凸起——灰度→法线纯函数，进既有 TextureCache）；
  2. **程序化环境贴图**（PMREM + 光带面光源风格）一张全局共享，金属框/稀有度框获得真实反射；
  3. 粗糙度分层：纸面 0.7 / 金属框 0.25；传说卡 clearcoat 全息闪层随视角流动；
  4. 材质按稀有度 ≤5 档全局共享，禁 per-card 克隆；fxQuality low 档直通旧扁平材质（降级保底）。
- **验收标准**：
  - 转动卡牌可见反射与浮雕层次；传说卡与普通卡材质肉眼分层；
  - 纹理缓存命中不重生成；中端设备 60fps；low 档回退不报错。

### P2-R3D2 牌桌真实材质

- **执行 agent**：client-3d ｜ **依赖**：P2-R3D1（共用环境贴图基建）｜ **工作量**：M
- **内容**：台面绒布加织纹法线贴图与粗糙度贴图（光池区域更光滑），MeshStandardMaterial 全套；槽位格线/螺母徽记凹凸化；场景灯双灯比（暖顶光 + 冷补光）营造实摄影感；派系染色过渡逻辑零回归。
- **验收标准**：绒布在光池边缘可见织纹起伏；两侧派系染色平滑过渡不回归；帧率达标；tableSkin 既有测试全绿。

### P2-UI1 界面可读性改版

### P2-UI2-2 沙箱效果预览面板

- **执行 agent**：client-ui（面板/驱动）+ client-3d（演示机位可选）｜ **依赖**：P2-UI2-1 ｜ **工作量**：M-L

## 3. 批次 γ · 教程 + 先手平衡 + AI 复盘

### P2-EDU1 体系化教程（五关，零教学专用卡）

- **执行 agent**：client-ui（教程控制器）+ card-content（教学卡组与文案）｜ **依赖**：无（单体最大，建议 γ 内最早启动）｜ **工作量**：L
- **设计（五关）**：
  | 关 | 名称 | 教学内容 | 过关目标 |
  | --- | --- | --- | --- |
  | 1 | 通电 | 供电/回合/结束回合 | 一个回合内打出 3 张卡 |
  | 2 | 上机 | 出牌/攻击/信仰充值 | 摧毁敌方一台显卡 |
  | 3 | 关键词七连 | 七关键词逐节讲解 | 逐节「必用该关键词」才能过关（如用三年质保挡一刀、用无输出亮机卡骗一刀） |
  | 4 | 派系对决 | 自选派系打一整局 | 善用 3 次派系技能 |
  | 5 | 自由实战 | 进入真对局 | 前 3 回合保留提示气泡 |
- **技术方案（引擎零改动）**：
  1. 每关 = 固定 seed + 教学预组卡组 + **脚本对手**（动作序列脚本——引擎确定性保证对局可精确编排；或按回合触发的轻规则）；
  2. **教学卡组全部从现有 90 卡池组装**（`content/decks/tutorial-*.json`，属预组卡组范畴，不新增卡 id）——关键词关的素材现成：taunt=Mac Pro 2013、divine_shield=AppleCare+、charge=天玑 9300、windfury=M1 Ultra、deathrattle=Helio G99、stealth=MacBook Air M2、overload=Exynos 8895；
  3. 教程控制器拦截 UI：动作白名单过滤（基于 getLegalActions 收窄）、目标高亮、气泡文案、失败即时重试；
  4. 过关判定消费真实事件流（如检测 divine_shield 的 shieldConsumed）；
  5. 跳关/重玩/任意关卡直达，进度存 localStorage。
- **验收标准**：
  - **从未玩过的真人 15 分钟内通关并独立开一局真对局**（用户亲自或找一名新玩家实测）；
  - 跳关/重玩不破坏进度；教程内引擎行为与真实对局完全一致（同一套四函数接口）；
  - 教程内容（卡组/脚本/文案）全部数据驱动，改动不碰控制器代码。

### P2-ENG1 先手平衡 · 电费抵扣券（WF-ENGINE）

- **执行 agent**：engine-dev（引擎）+ qa-balance（复测）+ 四端同步（client-ui/net-dev）｜ **依赖**：决议已拍板 ✓ ｜ **工作量**：M（本体）+ 基线重录与全端同步
- **机制定稿**：
  - 后手玩家（P2）在 `initGame` 起手阶段额外获得一张**电费抵扣券**：一次性卡，**打出后本回合供电 +300W（可超 1000W 上限）**，回合结束未用部分失效；不占卡组 30 张名额（起手照旧 3 张 + 券）；
  - 券为引擎内建特殊卡，不进 content 可收集池；type 归类与卡面由 engine-dev 按 schema 现状定夺并在汇报中说明（卡面走 cardArt 既有渲染，显示金色）。
- **契约变更（走 WF-ENGINE 完整流程）**：
  1. 事件目录新增 `COIN_GRANTED`（或并入 CARD_DRAWN 加 source 标记——由 engine-dev 评估后定稿，rules.md §6 升版）；
  2. constants 新增 `VOUCHER_BONUS = 300`；
  3. rules.md §2 回合流程 / §9 胜负疲劳 相应条款更新，版本号 bump（§13）；
  4. **黄金回放基线全部重录**（initGame 行为变化影响所有新对局），版本注记写明；
  5. 下游逐个通报：client / server / cli / ai（AI 需学会用券——evaluate 层加券的时机启发式）。
- **补偿量跑参**：在特性分支先落最小引擎改动 → bench 跑数 → 校准 +300W（若 P1 仍 >56% 或 <52%，调 200/400W 档位重跑）→ 定稿合并。
- **验收标准（量化）**：
  - bench 复测（每配对 ≥300 局）：**先手胜率落在 52%~56%**；
  - **派系胜率极差仍 <10pp**；
  - 新黄金基线全绿；client/server/cli/ai 四端同步上线无漂移（LAN 双端版本一致性测试过）；
  - 回放兼容：旧回放（无券版本）标注 schemaVersion，播放器按录制动作重放不受影响（重放走录制序列，不依赖当前 initGame 语义）。

### P2-QA1 AI 复盘

- **执行 agent**：game-ai（评分引擎）+ client-ui（报告 UI）｜ **依赖**：P2-UI3 ｜ **工作量**：M-L
- **内容**：
  1. 回放页「AI 复盘」按钮：对己方每个决策点，Hard AI 在同局面给出它的选择与评估值，与实际选择对比 → **单步评分 S/A/B/C**（评估差阈值分档）；
  2. **漏斩检测**：legalActions 枚举 + 推进一步扫描是否存在一击致死线路而未执行；
  3. 复盘报告卡：总评分曲线 + Top3 失误步骤（点击跳转回放位置）+ 尽力解释（分差分解到「少打脸 X 伤 / 多亏 Y 卡」粒度，解释不了只给分差，不硬编故事）；
  4. 红线：AI 只走公开接口（防作弊封印闸门照旧）；本地计算、可取消、不阻塞 UI。
- **验收标准**：
  - 30 步对局 10 秒内出报告；已知失误样本（人工构造）能被正确标低分；
  - 漏斩检测在构造的斩杀局面下 100% 检出、无非漏斩误报；
  - 防作弊闸门测试不回归。

## 4. 依赖关系与并行度

```
批次 α
  P2-INF1 回放存储 ──┬── P2-UI3 回放播放器 ──（γ）P2-QA1 AI 复盘
                     └── P2-DATA1 数值面板（个人历史部分）
  P2-UI2-1 白话翻译器 ── P2-UI4 全卡图鉴 ──（β）P2-UI2-2 沙箱预览
  P2-UI5 自定义快捷键（独立，随时可开工）

批次 β（可与 α 尾段并行）
  P2-R3D1 卡牌材质 ── P2-R3D2 牌桌材质（共用环境贴图）
  P2-UI1 可读性（独立）
  P2-UI2-2 效果预览（依赖 α 的翻译器）

批次 γ
  P2-EDU1 教程（单体最大，γ 内最早启动）
  P2-ENG1 抵扣券（拍板✓ → 分支跑参 → WF-ENGINE → 四端同步 + 基线重录）
```

- 同批次内互不依赖的任务可多代理并行（按文件域切界：ui/three/content 隔离，参照一期两轮演出升级的并行经验）；
- β 与 α 尾段可跨批并行；γ 需等 α/β 收口（用户验收节奏）。

## 5. 风险与对冲

| 风险 | 对冲 |
| --- | --- |
| IndexedDB 配额/隐私模式受限 | 降级路径：写不进时提示「回放仅本场可看」，不影响对局本身 |
| 拟真材质性能回退 | 法线/环境贴图全共享缓存；low 档直通扁平材质 |
| 回放跨版本不可用 | schemaVersion + stableHash 双校验，明确提示不静默失败 |
| AI 复盘解释力不足 | 只承诺评分与分差；解释做到哪层算哪层 |
| 教程工作量大烂尾 | 五关独立可发布；引擎零改动；脚本对手比 AI 便宜得多 |
| 抵扣券破坏现有平衡 | 分支先跑参校准补偿量再合并；bench 复测量化验收 |
| 键位冲突/浏览器保留键 | 冲突检测强制交换或改选；保留键（Ctrl+Tab 等）编辑器直接拒收 |

## 6. 发布与验收节奏

1. 每批次收口：全仓门禁（typecheck/test/build）→ 提交推送 → CI/Pages 自动上线 → **用户 WF-VISUAL 人工验收**；
2. 批次验收通过才开下一批次；
3. P2-ENG1 合并时黄金基线重录与 rules.md 版本 bump 同 PR 完成，LAN 双端同步（server 与 client 必须同版本对局）；
4. 二期全部收官后 tag：`v0.2.0`（一期 tag `v0.1.0` 仍待用户定名打点）。
