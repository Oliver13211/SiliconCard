## 0. 总览与目标

一期解决了「有得玩、玩得好」：引擎确定性、7 派系 90 卡、三对局来源、平衡管线、演出音效全部落地。二期解决「玩得深、留得住」：

1. **观感再上一档**——拟真材质取代扁平观感，界面信息可读性重排，卡牌效果可视化预览；
2. **复盘闭环**——回放 + AI 复盘 + 数值面板，让每局对局都能变成经验；
3. **新玩家通道**——体系化教程把规则学习融进模拟对战，图鉴兜底查阅；
4. **竞技公平**——实测 +9pp 的先手优势做引擎级补偿；
5. **手感杂项**——快捷键出牌等体验补齐。

**不做（延续 YAGNI）**：天梯/账号系统、服务器持久化对战记录、移动端适配、卡池商业化、回放云端分享站。回放先做本地（IndexedDB + 文件导入导出），分享走导出 JSON 文件。

### 三批次路线图

| 批次 | 主题 | 任务 | 出口标准 |
| --- | --- | --- | --- |
| **P2-α 快赢** | 回放闭环 + 图鉴 + 快捷键 | P2-INF1, P2-UI3, P2-DATA1, P2-UI4, P2-UI5 | 对局可回放可导出；90 卡图鉴可查；全程键盘可打 |
| **P2-β 观感** | 拟真材质 + 预览 + 可读性 | P2-R3D1, P2-R3D2, P2-UI1, P2-UI2 | 用户 WF-VISUAL 验收通过 |

## 1. P2-VIS 观感与可读性

### P2-R3D1 拟真卡牌材质（R3D）

- **现状**：卡牌是贴图平面 + BackSide 描边，观感偏「纸片」。
- **方案**：`MeshPhysicalMaterial` 升级——① 卡面 Canvas 生成时同步派生**法线贴图**（边框浮雕、插画窗下沉、金属框凸起，灰度→法线的纯函数）；② `PMREMGenerator` + 程序化环境贴图（机房 HDR 风格：几块光带面光源），让金属框/稀有度框有真实反射；③ 粗糙度分层（纸面 0.7 / 金属框 0.25 / 全息传说层做 clearcoat）；④ 传说卡加微弱 clearcoat 闪层，随角度流动。
- **性能红线**：环境贴图全局共享一张；法线贴图按 cardId 进既有 TextureCache；材质按稀有度五档共享（普通/稀有/史诗/传说 × 双面），禁 per-card 材质克隆。
- **验收**：同一张卡在光下转动可见材质层次变化；帧率不破 60（中端设备）；纹理缓存命中不重生成。
- **工作量**：M（中）。风险：法线贴图生成质量需 WF-VISUAL 多轮目检。

### P2-R3D2 牌桌真实材质（R3D）

- **现状**：tableSkin 已有程序化 Canvas 纹理（绒布/机架墙/地板），但走基础贴图，无光照响应层次。
- **方案**：① 台面绒布加**法线贴图**（织纹凹凸）与粗糙度贴图（光池区域更光滑），MeshStandardMaterial 全套；② 槽位格线/螺母徽记做凹凸；③ 环境贴图与 P2-R3D1 共用；④ 场景灯加暖色顶光 + 冷色补光的双灯比（实摄影感）。
- **验收**：绒布在光池边缘可见织纹起伏；派系染色过渡不回归；帧率达标。
- **工作量**：M。依赖：与 R3D1 共享环境贴图基建，串行做省一次搭建。

### P2-UI1 界面可读性改版（UI）

- **现状**：tokens.css 已统一设计令牌，但信息密度与层级未经可读性专门打磨（用户反馈「更加可读」）。
- **方案**：① 正文字号/行高/对比度整体上调（WCAG AA 起步）；② 血条/功耗条数值区加大加粗，状态语义色（可打/禁用/充足/不足）统一；③ 手牌区收窄装饰、留白让位给牌名与费用；④ 事件日志按回合分组折叠，重要事件（斩杀/跳闸/质保破）高亮；⑤ 长卡名截断策略与 tooltip。
- **验收**：1080p 与 1440p 下无需眯眼；用户目检通过。
- **工作量**：S-M。

### P2-UI2 卡牌效果预览（UI，本批亮点）

- **方案**：选中/悬停卡牌出预览面板，两层内容：
  1. **白话解释**——把 EffectSpec 步骤序列翻译成人话（`damage chosen anyCharacter 3` → 「指定任意角色造成 3 点伤害」），规则化翻译器放 content 侧解释层，不改引擎；
  2. **沙箱迷你演示**——**这是无头引擎的杀手级应用**：`initGame` 起一个固定演示局面（测试基建现成），脚本化打出这张卡，把产出事件流喂给一个 2D 演示画布（或直接复用 3D 场景切演示机位），动画循环播放。零逐卡内容成本，卡池扩充自动获得预览。
- **验收**：90 张卡全部有解释 + 可播放演示；效果改动后预览自动同步（无手工维护面）。
- **工作量**：M-L（翻译规则 + 演示驱动器）。依赖：无。派发：UI + card-content（白话翻译表）协作。

## 2. P2-REP 回放与复盘

### P2-INF1 回放录制与存储（INF）

- **现状**：core 已有全套回放基建——`ReplayRecording` 序列化、canonicalJson、FNV-1a stableHash、黄金回放测试。缺的只是客户端落盘与 UI。
- **方案**：① battleDriver 在对局中静默记录 `setup + 动作序列`；② GAME_END 落 IndexedDB（元数据：日期/对阵派系/胜负/局长/种子）；③ 导入导出 JSON 文件（分享回放）；④ 打开回放时先 stableHash 校验完整性，不匹配提示「回放与当前卡池版本不符」。
- **验收**：本地/人机/局域网三种对局均可录可放；hash 校验拦截版本漂移。
- **工作量**：S-M。**这是全期 ROI 最高的任务——引擎白送的。**

### P2-UI3 回放播放器（UI）

- **方案**：① 播放器 = 按录制动作序列重驱引擎（确定性保证逐帧一致），复用 battleDriver + 三维场景全量演出与音效；② 控制条：播放/暂停/变速（0.5×/1×/2×/4×）/逐事件步进/拖动时间轴（按事件索引 seek：seek = 从头快放至目标，引擎重放是毫秒级）；③ 双方手牌信息在回放中**全量可见**（回放是上帝视角，兼做复盘）；④ 事件日志侧栏与时间轴联动，点日志跳转。
- **验收**：任意一局可从任意事件点继续播放且状态与原局一致；演出音效完整。
- **工作量**：M。

### P2-QA1 AI 复盘（QA/AI）

- **现状**：@siliconcard/ai 的 Hard 档 + evaluate 函数可直接复用；QA2 管线已有逐局评估经验。
- **方案**：① 回放页「AI 复盘」按钮：对己方每个决策点，让 Hard AI 在同局面给出它的选择与评估值，与实际选择对比 → **单步评分 S/A/B/C**（评估差阈值分档）；② **漏斩检测**——扫描是否存在一击致死线路而未执行（legalActions 枚举 + 模拟推进一步即可判）；③ 复盘报告卡：总评分曲线 + Top3 失误步骤（可点击跳转回放位置）+ 一句话原因（评估差分解到「少打脸 X 伤 / 多亏 Y 卡」粒度，尽力而为，解释不了就只给分差）。
- **红线**：AI 只走公开接口（防作弊封印闸门照旧）；复盘计算本地完成，可取消。
- **验收**：一局 30 步对局复盘 10 秒内出报告；明显失误能被标出。
- **工作量**：M-L。依赖：P2-INF1/P2-UI3。

### P2-DATA1 数值面板（QA/DOC）

- **方案**：两层数据源——
  1. **全局模拟数据**（离线预生成）：跑 `cli bench` 管线产出派系胜率/卡牌出场率/打出后胜率（playedWin），生成 JSON 随包发布，图鉴与数值面板消费——玩家不用等自己攒样本就有参考；
  2. **个人对局历史**（本地）：从回放库聚合个人胜负/常用派系/卡牌使用率。
- **验收**：派系胜率极差等关键数字有口径说明（对齐 balance 报告）；个人数据仅存本地。
- **工作量**：S-M。

## 3. P2-EDU 图鉴 / 教程 / 杂项

### P2-UI4 全卡牌图鉴（UI）

- **方案**：① 90 卡瀑布网格，筛选器（派系/稀有度/类型/费用曲线）+ 排序；② 卡面直接复用 cardArt 渲染管线（同源无第二套视觉）；③ 详情 = 大图 + 白话解释（复用 P2-UI2 翻译器）+ 沙箱演示入口 + flavor + 平衡数据（P2-DATA1 的出场率/打出胜率）；④ 未拥有/全部可见（本游戏全卡开放，图鉴是学习工具不是收集墙）。
- **验收**：新卡入池自动进图鉴（零登记）；筛选项全组合可用。
- **工作量**：M。依赖：P2-UI2 的翻译器与演示器（复用），可与 α 批次其他任务并行。

### P2-EDU1 体系化教程（UI，工作量最大的单体）

- **设计**：任务制闯关，规则学习融进模拟对战——
  - **第 1 关「通电」**：供电/回合/结束回合概念。半开放对局：对手按脚本走，目标「用一个回合内打出 3 张卡」。
  - **第 2 关「上机」**：出牌/攻击/信仰充值。目标「摧毁敌方一台显卡」。
  - **第 3 关「关键词七连」**：七关键词逐个讲解 + 当关必用该关键词才能过关（如「用三年质保挡下一次攻击」「用无输出亮机卡骗一次攻击」）。
  - **第 4 关「派系对决」**：选一个派系打一整局（对手轻度 AI），派系技能引导使用。
  - **第 5 关「自由实战」**：送进真对局，带前 3 回合提示气泡。
- **技术方案**：**教程 = 受约束的对局**，引擎零改动——① 每关 = 固定 seed + 预组教学卡组 + 脚本对手（脚本走动作序列或轻规则，不轮 AI）；② 教程控制器拦截 UI：限制可用动作（如只许点指定卡）、高亮目标、气泡文案；③ 过关判定消费事件流（如检测 divine_shield 消耗事件）；④ 跳过/重玩/任意关卡直达；⑤ 教程卡组可含演示专用「教学卡」（content 侧新增，标注 tutorial 不进对战卡池）。
- **验收**：**从未玩过的真人 15 分钟内通关并独立开一局真对局**；跳关后不破坏任何进度。
- **工作量**：L（五关内容 + 控制器）。派发：client-ui（控制器）+ card-content（教学卡与文案）。

### P2-ENG1 先手优势平衡（ENG/QA，策划向，需拍板）

- **现状**：QA2 实测先手胜率 **59.4%**（镜像 59.7%，三种子 59.4–59.9%），约 +9pp——统计已对称抵消，但体验层是真实的不公平。
- **候选方案对比**（推荐 B，主题契合度与成熟度最高）：

| 方案 | 机制 | 补偿强度 | 主题梗 | 风险 |
| --- | --- | --- | --- | --- |
| A 错峰用电 | 后手首回合供电恢复 +100W（首回合可用 200W） | 中 | 「错峰电价」 | 弱势后手卡组可能仍不够 |
| **B 电费抵扣券（推荐）** | 后手起手附加一次性卡：本回合供电 +300W 可超上限 | 强 | 「电费红包」 | 炉石硬币的成熟范式，被验证过 |
| C 先手禁足 | 先手首回合禁止出牌 | 强 | 「开机自检」 | 挫败感强，先手体验受损 |
| D 后手多抽 1 | 后手起手 4 张 | 弱 | — | 30 卡库抽牌边际收益低 |

- **改动面**：`initGame` 发牌逻辑 + 可能新增事件（如 `COIN_GRANTED` 或并入 CARD_DRAWN）→ **走 WF-ENGINE 契约流程**：事件目录冻结版 rules.md §6 升版、黄金回放基线重录（版本号 bump，rules.md §13）、client/server/cli/ai 四端同步。
- **验收（量化）**：bench 复测——① 先手胜率回落至 **52%~56%** 区间；② 派系极差仍 **<10pp**；③ 新黄金基线 4 局全绿。
- **工作量**：M（本体）+ 全端同步与基线重录。**前置：用户对方案拍板后才能开工。**

### P2-UI5 快捷键出牌（UI）

- **方案**：① 手牌槽位键 `1-9、0` 打出对应手牌（可打才响应，配合既有 reason 提示）；② `空格` 结束回合；③ `H` 英雄技能；④ `Tab` 循环选中合法目标，`Enter` 确认，`Esc` 取消；⑤ `F` 快进演出、`M` 全局静音、`?` 键位表浮层；⑥ 快捷键提示直接画在手牌槽位角标上（可关）。
- **验收**：不碰鼠标完成一整局；键位表内所有键可自定义与否记录为后续项（一期先固定）。
- **工作量**：S-M。

## 5. 风险与对冲

| 风险 | 对冲 |
| --- | --- |
| 拟真材质引发性能回退 | 法线/环境贴图全共享缓存；低配档（fxQuality low）保留扁平材质直通 |
| 回放文件跨版本不可用 | stableHash 校验 + 版本号写入元数据，不匹配明确提示 |
| AI 复盘解释力不足（为什么错说不清） | 只承诺评分与分差，解释做到哪层算哪层，不硬编故事 |
| 教程工作量大导致烂尾 | 五关各自独立可发布，做完一关上一关；引擎零改动保证不卡壳 |
| 先手补偿破坏现有平衡 | bench 管线现成，补偿量先在沙箱跑参再动引擎；黄金基线重录一次到位 |
| 90 卡白话翻译规则覆盖不全 | 翻译器先覆盖 12 原语全组合，漏网的卡回退显示原始效果 JSON + 人工补表 |

## 6. 评审确认清单（开工前需要用户拍板的）

1. 三批次顺序是否认可（α 回放快赢 → β 拟真观感 → γ 教程与平衡）；
2. 先手平衡方案选哪个（推荐 B 电费抵扣券）；
3. 回放存储上限（建议本地保留最近 50 局 + 导出归档）；
4. 教程是否需要「教学专用卡」（建议需要，约 6-8 张，不入对战卡池）；
5. 快捷键一期固定键位是否可接受（可自定义放后续）。
